# 本地开发环境说明（暂用本机 MySQL / Redis，Docker 已暂退）

> 更新时间：2026-09-18
> 决策：开发阶段直接使用本机 MySQL 与 Redis，`docker-compose.yml` 编排暂时搁置。
> 原因：减少容器依赖、加速本地迭代；本机已具备 `MySQL84(3306)` 与 `redis(6379)` 服务，且经实测可直接承载本项目。

---

## 1. 本机依赖（实测）

| 依赖 | 服务名 | 端口 | 口令 | 状态 |
|---|---|---|---|---|
| MySQL | `MySQL84` | 3306 | `root / 1234`（实测可登录） | Running |
| Redis | `redis` | 6379 | 无口令 | Running |
| 数据库 | `clawbot` | — | — | 已存在（Flyway 首次启动自动建表迁移） |

> 注意：本机 MySQL 3306 的 root 口令经实测为 `1234`（此前记忆笔记称“非 1234”已被证伪，以实测为准）。Redis 无需口令。

## 2. 后端启动（local profile，连本机）

```bash
cd backend
SPRING_PROFILES_ACTIVE=local \
DB_HOST=127.0.0.1 DB_PORT=3306 DB_NAME=clawbot DB_USERNAME=root DB_PASSWORD=1234 \
REDIS_HOST=127.0.0.1 REDIS_PORT=6379 \
WX_TOKEN=clawbot-local-token ADMIN_INIT_PASSWORD=Admin@123456 \
java -jar target/clawbot-backend.jar
```

要点：
- `DB_HOST` 用 `127.0.0.1` 而非 `localhost`，避免 Windows 下 mysql-connector 将 `localhost` 当作命名管道。
- `DB_PORT` / `REDIS_PORT` 默认即 3306 / 6379，可省略；口令为空时 `DB_PASSWORD` 留空即可（本机 MySQL 需显式填 `1234`）。
- 后端配置 `application.yml` 默认即 `localhost:3306` / `localhost:6379`，故不传 DB_* 也能连本机，仅需补 `DB_PASSWORD=1234`。

## 3. 端到端走查（已在本机环境验证：7 PASS / 0 FAIL / 1 SKIP）

```powershell
# 本机仅 Windows PowerShell 5.1（无 pwsh），脚本已兼容：
powershell -File scripts/e2e-smoke.ps1 -AdminPassword Admin@123456
```

兼容性说明（脚本已修）：
- 文件须 **UTF-8 带 BOM**，否则 PS 5.1 以系统 ANSI(GBK) 读 `.ps1` 致中文乱码、解析失败。
- 已弃用 `-SkipHttpErrorCheck`（PowerShell 7 专属），改用自写 `Invoke-WebRequestSafe`（基于 .NET `HttpWebRequest`，4xx/5xx 不抛、返回 `{StatusCode, Content}`）。
- 绕过 PS 5.1 非交互模式 `Invoke-WebRequest` 抛 `PSInvalidOperationException` 的坑。

> AC-E3（OPERATOR 越权 403）需先创建运营账号并传 `-OperatorToken` 重跑，当前为 SKIP。

## 4. 如需恢复 Docker 编排（未来）

- 本机 `MySQL84` 已占用 3306。`docker-compose.yml` 中 mysql 服务映射 `${DB_PORT:-3306}:3306`，会与本机冲突。
- 恢复二选一：
  1. 先 `net stop MySQL84` 停本机 MySQL，再 `docker-compose -p clawbot up -d`；
  2. 或修改 `.env` 中 `DB_PORT` 为其他端口（如 13306），使容器映射非冲突端口。
- Docker MySQL 初始口令由 `MYSQL_ROOT_PASSWORD` 决定（默认 1234），与本机库数据不互通，需重新迁移 / 导入。

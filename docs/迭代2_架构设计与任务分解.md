## 0. 结论前置小结

1. **架构形态不变**：继续 MVP 分层单体（ADR-001），五能力落到 `domain/tool/impl/`（4 个新 `@Component Tool`）+ `domain/port/`（5 个能力端口上提）+ 既有编排/一致性格。
2. **依赖铁律解法是"上提领域端口"**：现有 `infrastructure/client/{logistics,map,tts}` 与 LLM 视觉的接口/DTO **上移到 `domain/port/`**，基础设施 Mock/Real 实现改为实现领域端口（infra→domain 合法）。新增工具的 `domain` 层**绝不**依赖 `infrastructure`，铁律 0 破坏。
3. **五能力端到端 = 注册即暴露**：新增 4 个 Tool（命名已被 `ActionClaimExtractor` 预置语义 `recognize_image/synthesize_voice/query_express/plan_route`），经 `ToolRegistry` 构造器注入**零改动注册**，自动进入 LLM 函数 Schema（`AgentOrchestratorImpl:158`）。
4. **反幻觉基础版可行性已具备大半**：`RuleBasedConsistencyChecker`/`ActionClaimExtractor` 已预置 4 新工具语义；FR-09 收尾仅需①补全"识别/生成"完成态动词②让新工具全类型进入 `executed` 事实集（编排器已做）③补 ≥20 泄漏场景测试。Mock 工具亦写 `executed` 集，**泄漏=0 证据无需真实外部服务**。
5. **工程门禁**：后端追加 JaCoCo（行≥70%/分支≥60%）与 Checkstyle/SpotBugs 门禁（NFR-MA-04/09），缺口见 `ci.yml:6-7`。
6. **范围扩张（FR-09前移/A-2/B-2/证据闸门）依赖 TODO-12/13/14 经 11.3 确认**；确认前按 4.5 原基线排期，确认后追加（见 §7）。

## 2. 逐模块实现方案

> 每个工具与 `ManagePetProfileTool` 的**异同**已对比；"Mock 可验收性"对应 PRD §4 验收判据。

### 2.1 FR-10 图片识别工具（recognize_image）+ FR-06 多模态闭环

- **实现思路**：复用 MVP 已落地的 `LlmClient.vision(VisionRequest)`（class-diagram L112）。新增领域端口 `VisionPort`，由 infra `LlmVisionAdapter` 委托 `LlmClient.vision` 实现（保持 `LlmClient` 不动）。`RecognizeImageTool` 入参含 `image_url/base64` + `scene`(pet/object/ocr) + `question`；调用 `VisionPort` → 低置信（结果含 uncertain 标记）一律用"可能/疑似"措辞；模糊图返回 `EMPTY_RESULT` 不虚构；可经 `PetProfileService.findLiveByName` 由品种反查档案称谓（"识别到柯基→命中档案豆豆"，呼应 FR-14 贯通）。
- **关键类**：`VisionPort`、`LlmVisionAdapter`、`RecognizeImageTool`、`PetProfileService`（复用）。
- **与 ManagePetProfileTool 异同**：同 = 均 `@Component Tool`、构造器注入、结构化失败回注（BR-10）、不抛异常；异 = `idempotent=true`（只读）、`critical=false`（识别失败降级而非中断）、多依赖一个端口 `VisionPort` + 可选 `PetProfileService`。
- **FR-06 闭环**：无新类；验收 = recognize_image 的 pet/object/ocr 三场景 + 编排器内 vision 调用失败的降级（复用 `FallbackService` 不外露 stack trace，PRD FR-06 验收）。
- **Mock 可验收性**：✅ 桩 `vision` + 契约测试；TODO-03 未结亦可验收。

### 2.2 FR-11 语音生成工具（synthesize_voice）

- **实现思路**：`SynthesizeVoiceTool` 调 `VoiceSynthesisPort.synthesize(text,voiceId)` → 原始音频经 `MediaTranscodeService`（ffmpeg 转 amr/speex，微信语音媒体要求，RSK-14）→ `MediaDispatchPort.sendVoice(openid,bytes,filename)`（infra `WechatMediaDispatchAdapter` 用 `WechatTransport.uploadTempMedia`+`sendCustomerMessage` 下发）→ 返回"已为你生成语音，请查收"。TTS 失败回退文字（"语音暂时无法生成，以下是文字：…"），不损坏音频、不抛。
- **关键类**：`VoiceSynthesisPort`、`MediaDispatchPort`、`MediaTranscodeService`、`WechatMediaDispatchAdapter`、`SynthesizeVoiceTool`、`WechatTransport`（复用 L166-167）。
- **与 ManagePetProfileTool 异同**：同 = 结构化结果 + 日志；异 = `idempotent=false`（下发是副作用，不可自动重放）、`critical=false`、依赖 2 端口 + 转码服务。
- **Mock 可验收性**：✅ `MockTtsClient` 返回确定性字节 + ffmpeg 转码（镜像内置）+ Mock 通道；真实微信播放验证并行（PRD FR-11 验收②）。

### 2.3 FR-12 快递工具（query_express）

- **实现思路**：`QueryExpressTool` 调 `ExpressQueryPort.query(companyCode,trackingNo)`；`companyCode` 由运单号前缀（如 SF=顺丰）或参数推断，覆盖顺丰/中通/圆通/韵达/邮政/京东 6 家（PRD FR-12 验收①）；`ExpressTrace.found=false` 返回"未查到，请核对单号"，**不编造节点**；运单号在 `log_tool_call.params_json` 经 `MaskUtils` 脱敏（BR-15/NFR-SE-04）。
- **关键类**：`ExpressQueryPort`、`MockLogisticsClient`(改挂端口)、`RealLogisticsClient`(TODO-04)、`QueryExpressTool`。
- **与 ManagePetProfileTool 异同**：同 = `@Component`、失败回注；异 = `idempotent=true`、`critical=false`、入参为单号非档案。
- **Mock 可验收性**：✅ Mock 契约测试（PRD FR-12 验收③④）。

### 2.4 FR-13 导航工具（plan_route）

- **实现思路**：`PlanRouteTool` 调 `MapNavigationPort.geocode(address)`→`planRoute(from,to,mode)`→ 产出可跳转链接（移动端可开）。**坐标仅临时使用、绝不落库**（BR-17，PRD FR-13 验收④：DB 快照核验坐标为空）；失败返回"暂时无法规划路线"。
- **关键类**：`MapNavigationPort`、`MockMapClient`(改挂端口)、`RealMapClient`(TODO-04)、`PlanRouteTool`、`GeoPoint`(GCJ-02，BR-16)。
- **与 ManagePetProfileTool 异同**：同 = `@Component`；异 = `idempotent=true`、`critical=false`、**无任何持久化调用**（与 ManagePetProfileTool 形成对照：导航零写库）。
- **Mock 可验收性**：✅ Mock 契约测试（PRD FR-13 验收①③）。

### 2.5 FR-14 宠物档案贯通

- 无新类。`RecognizeImageTool` 在识别到品种时调用 `PetProfileService.findLiveByName(openid, breed映射名)` 命中档案称谓。补一条集成测试："识别到柯基→命中档案豆豆"（PRD FR-14 验收）。

### 2.6 FR-09 执行一致性校验前移收尾（MVP 已具备大半）

- **现状**：`AgentOrchestratorImpl` 已注入 `ConsistencyChecker`(L221) 与 `ContentSafetyService`(L213 Fail-Closed)；新工具执行均经 `executeOne` 写入 `executed`（`ToolCallRecord.withOutcome`，L305）；`ActionClaimExtractor.toolSemantics` 已预置 `recognize_image/synthesize_voice/query_express/plan_route`（MVP 前瞻）。
- **收尾改动（仅 2 处 + 测试）**：
  1. `ActionClaimExtractor` 补完成态动词「识别」「生成」入 `COMPLETION_PATTERN`（当前缺"识别"，导致"已识别为柯基"类声明漏检）；`VERB_KEYWORD` 加映射。
  2. 确认 5 类工具 `ToolStatus` 映射正确（SUCCESS 才支撑，DEGRADED/TIMEOUT/FAILED 均判不支持 → 拦截）。
  3. 新增 ≥20 组"工具全失败但模型声称成功"泄漏场景测试（TC-H 子集），断言 `EXECUTION_HALLUCINATION` 拦截且拦截日志含 `traceId`（PRD KR2、FR-09 验收②③）。
- **strict-mode 免责前缀**：已在编排器 L228-231 实现（SRS 9.4.5），本迭代不动。

### 2.7 TODO-05 意图识别语料库 ≥300 条（FR-05 验收解锁）

- 新增测试资产 `src/test/resources/intent-corpus/{train,test}.jsonl`（≥300 条标注样本，覆盖 5 业务意图 + chitchat + unknown）；`IntentCorpusLoader` 加载并驱动 `LlmIntentClassifierTest`（PRD TODO-05 验收）。纯测试资产，不进生产包。

### 2.8 FR-16 用户/宠物档案管理（管理侧，S）

- **实现思路**：复用 MVP `UserController`/`UserQueryService`/`PetController`。新增 `UserAdminService`（写：禁用/启用、档案维护），`UserStatusGate`（入站拦截：被禁用用户**不触发 LLM**，PRD FR-16 验收②——在 `WechatMessageService.handleInboundWithReceipt` 编排前查 `wx_user.status`）；`AuditLogService`（写 `log_audit` 前后值留痕，PRD FR-16 验收③）。OpenId 脱敏由 `MaskingAssembler` 复用（G-11）。
- **关键类**：`UserAdminService`、`UserStatusGate`、`AuditLogService`（新增写服务，MVP 仅有 `AuditLogQueryService` 读）。

### 2.9 FR-18 系统配置在线（S）+ B-2 多模型使能

- **实现思路**：复用 `ConfigController`(读)/`ConfigCacheService`。新增 `ConfigAdminService`（更新 `sys_config`、校验非法值、密钥不回明、变更留痕）；核心使能件 `DynamicConfigService`（`application/config`）：运行时从 `sys_config` 读+缓存，供编排器取 `disabled-tools`/`llm.model`/`strict-mode` 等 → **免重启生效**（PRD FR-18 验收①/FR-09 strict 切换）。B-2 由 `LlmClientRouter`（infra，实现 `LlmClient`）持有 Mock+Real，按 `llm.provider` 运行时路由 → 切换模型免重启（PRD B-2 验收①②）。
- **关键类**：`DynamicConfigService`/`DynamicConfigServiceImpl`、`ConfigAdminService`、`LlmClientRouter`。
- **注意**：`LlmProperties`/`OrchestrationProperties`/`SafetyProperties` 改为从 `DynamicConfigService` 取值（薄封装），移除纯启动期 `@ConfigurationProperties` 静态性。

### 2.10 A-2 回放调试台（S，依赖 `log_tool_call`）

- **实现思路**：复用 `ToolLogController`/`ToolLogQueryService` 读 `log_tool_call`（8 表已建，TODO-08）。新增 `ReplayService` + `ToolLogController.replay(ReplayRequest)`：按 `traceId`/日志 id 干跑——用存储的 `params_json` 重新调用当前工具实现得 `ToolResult`，并可对"给定回复+存储 executed 集"重跑 `RuleBasedConsistencyChecker` 以**复现幻觉拦截路径**（PRD A-2 验收①②）。无新表。
- **关键类**：`ReplayService`、`ReplayRequest`(DTO)。

## 2 产品目标与成功判据

### 2.1 产品目标（3 条，正交）

| 序 | 目标 | 说明 | 溯源 |
| --- | --- | --- | --- |
| G-1 | **主链路可离线跑通** | 无微信账号、无 LLM Key、无物流/地图/TTS 凭据时，仍能完成端到端演示与验收；真实凭据到位后仅改配置即可切换 | 约束 1；SRS 3.6.2 AS-01/02/03；8.4 SPI |
| G-2 | **"不可信的模型 + 可信的系统"** | 反幻觉与降级能力是本产品的差异化，必须在 MVP 内落地（而非收尾增强项）：执行性幻觉对外泄漏 = 0 | SRS 3.1 可靠层；2.3.5 L4；9.4.5；12.8 修订理由 1 |
| G-3 | **每一次"完成"都可自证** | 交付物附可复现证据（测试记录/接口报文/日志片段）；技术栈每一项有真实引用点；配置占位符不得带上线 | SRS 12.6.2 G1/G2/G3；附录 G-31/G-32 |

### 2.2 成功判据（可量化，≤3 条）

| 判据 | 目标值 | 验证方式（可执行） |
| --- | --- | --- |
| S-1 主链路可用性 | 仅启动本地 MySQL/Redis（无任何外网凭据），一条微信文本消息可从 Mock 通道进入并落库，端到端 P95 ≤ 3s（Mock LLM 模式） | 执行 20 次端到端脚本，统计耗时；`message` + `tool_call_log` 落库条数与请求数一致 |
| S-2 反幻觉 | 构造"工具全部失败/未执行但模型声称成功"场景 ≥ 20 次，**对外泄漏 = 0**；降级场景 100% 有可控文案 | 自动化用例 TC-H 组；比对回复文本与 `tool_call_log.status`；抽样日志核验无 stack trace / 内部错误码外露 |
| S-3 可运营与可自证 | 管理员可登录并检索到该次链路的 `tool_call_log` 与同 `traceId` 全链路日志；每个 P0 交付项附证据文件，无证据项不计完成 | 后台实测截图/报文 + 证据清单核对表（附录 G-31） |

## 5 需求池（P0 / P1 / P2）

- **P0**：MVP 必须交付**且可验收**（无此项即不构成 MVP）

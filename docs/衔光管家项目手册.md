## 第 1 章 项目概述

### 1.1 项目定位

衔光管家（Clawbot）定位为：**微信原生的单拥有方「个人 / 家庭执行型智能管家」**——一个装好即用、深读你的微信世界、能主动把事办了的专属助手。

核心特征：

- **微信原生入口**：以微信公众号 / 企业微信为唯一交互面，直接消费微信上下文（消息、群聊、文件、收藏、通讯录标签）。
- **执行型而非纯对话型**：核心目标是"把事办了"——记忆用户偏好、跨会话管理任务、主动提醒与跟进。
- **单拥有方、自治部署**：面向个人 / 家庭 / 小社群主理人，实例私有、数据私有，不依赖任何中心化平台。
- **主动触达**：通过微信模板消息 / 订阅通知 / 群@ 等能力，在无需用户发消息时也能行动。

> 与"通用对话助手"的本质区别：通用对话助手是"你问它答"；衔光管家是"你不用问，它替你记、替你盯、替你办"的私人执行体。现实对标范式是个人 Agent 的自主执行，而非聊天机器人。

### 1.2 目标用户与价值

| 用户 | 典型场景 | 衔光提供的价值 |
|---|---|---|
| 个人用户 | "把刚才群里说的聚餐时间记下来，到点提醒我" | 读群上下文 + 主动推送提醒 |
| 家庭 / 宠物主 | "记下猫咪疫苗下一针日期，提前一周提醒" | 长期记忆 + 微信订阅通知 |
| 小社群主理人 | "每周一把本周安排汇总发到群里" | 群@ + 定时触达 + 微信内动作 |
| 自由职业者 | "把文件传输助手的发票整理成记账" | 读取微信文件 / 收藏 + 结构化档案 |
| 隐私敏感用户 | "我的对话和档案只能在我自己的服务器" | 单拥有方自治部署，数据不出私域 |

价值主张：**把微信从"聊天工具"升级为"私人执行中枢"**——对话只是控制面，行动才是主产品。

### 1.6 重新定位说明（演进记录）

本项目早期基线（迭代 1~3）实现的是一个"微信对话助手内核"（LLM 中枢 + 工具 + 审计 + 限流 + 归档 + 配置 + 回放 + 多模型）。为使产品定位清晰、避免与"通用对话助手"同质化，项目完成一次**定位重锚**：

- **从**：通用对话助手（你问它答）。
- **到**：微信原生的私人执行型管家（你不用问，它替你记、盯、办）。

重锚后的目标架构在既有内核之上增加**三层执行体能力**（个人状态库 / 事件与触发引擎 / 主动执行器，均属规划·迭代 4），使系统从 turn-driven 转为 event-driven。既有内核（迭代 1~3）全部可复用，无需重写。

## 第 2 章 核心功能说明

> 章节前缀「已实现」表示有对应 `main` 源码与测试；「规划」表示重新定位后的下一阶段目标，未实现。

### 2.1 微信通道接入（已实现）

- **单一入口**：`interfaces/wechat/WechatController`（含 `WechatCallbackController`），路径 `/wechat/callback`；在 `SecurityConfig` 中 `permitAll()`，由 `WechatSignatureVerifier` 执行平台验签。
- **验签与去重**：sha1 字典序签名；±300s 时间窗；同 `MsgId` 幂等去重（Redis `dedup:msg:{msgId}`）。
- **消息路由**：`MessageDispatcher` 单一入口 + 类型参数化路由（text/image/voice/location/event 策略族）。
- **先回执后推送**：回调 ≤700ms 内返回回执，终态经有界线程池异步推送（BR-06）。
- **token 管理**：缓存前缀分域 + 提前过期 + 分布式锁 + 单次失效重试（SRS 9.4.6）。
- **Mock 与真实通道复用同一 Controller 与同一段验签代码**。

### 2.2 对话与模型中枢（已实现）

- **Agent Loop**：`AgentOrchestrator`（`AgentOrchestratorImpl`）执行多轮工具编排，受 SC-01~SC-05 状态机硬约束（轮次 / 并发 / 超时）。
- **分发门控**：`MessageDispatcher` 分发前经 `UserStatusGate` 拦截禁用用户（不触发 LLM）。
- **模型调用**：经 `LlmClient` 抽象；`LlmClientRouter` 运行时多 provider 路由（见 2.10）。
- **上下文**：`ContextStore` 端口 + token 裁剪，保持 tool/assistant 消息配对不变式（SRS 9.4.4）。
- **实时观测（FR-08）**：编排过程事件经事件总线推送至 SSE 通道 `/api/sse/console`（详见 2.12）。
- **系统人设**：预置"衔光"人格，零配置。

### 2.3 AI 工具（Function Calling）（已实现）

工具位于 `domain/tool/impl`，统一实现 `Tool` 接口（`describe()` / `invoke()`），由 `ToolRegistry` 构造器注入后**注册即暴露**进 LLM 函数 Schema。当前内置 5 个：

| 工具类 | 能力 | 备注 |
|---|---|---|
| `RecognizeImageTool` | 图片视觉识别（FR-10） | 语义 `recognize_image` |
| `SynthesizeVoiceTool` | 语音生成与发送（FR-11） | 语义 `synthesize_voice` |
| `QueryExpressTool` | 快递查询（FR-12） | 语义 `query_express` |
| `PlanRouteTool` | 导航服务（FR-13） | 语义 `plan_route` |
| `ManagePetProfileTool` | 宠物档案管理（FR-14） | 声明 `readOnly()` 支持回放护栏 |

- 工具调用全程审计（`log_tool_call`，`call_seq` 递增）。
- 外部集成类工具为衔光自主实现，作为执行循环内部能力，不对外开放为市场。

### 2.4 反幻觉与一致性校验（已实现）

- **执行一致性校验**：`ConsistencyChecker`（`RuleBasedConsistencyChecker`）+ `ActionClaimExtractor`——当模型声称"已完成某动作"但无对应工具执行记录时，判定 `CLAIM_UNSUPPORTED` 并拦截（FR-09）。
- **内容安全 Fail-Closed**：`ContentSafetyService` 词库不可用时按 Fail-Closed 处理。
- **兜底文案**：模型不可用或越界时返回受控兜底话术（可由后台热改）。
- **目标**：执行性幻觉对外泄漏 = 0（迭代 2 已构造 ≥20 泄漏场景验证，全部拦截留痕）。

### 2.5 审计与安全基线（已实现）

- 全量敏感操作写入 `log_audit`（增删改、用户启停、配置变更、回放等），前后值留痕（`before`/`after`）。
- 越权访问返回 403 并落痕；出参统一脱敏（`interfaces/assembler`，手机号 / OpenId）。

### 2.6 限流与成本预算（已实现）

- `RateLimitDecision` 枚举化决策；用户 / IP 双令牌桶 + 白名单豁免 + Fail-Open（FR-20）。
- `CostBudgetServiceImpl` 成本预算控制；限流事件落 `log_rate_limit`。
- 设计约束：多构造器 Bean 须显式标 `@Autowired`（见 6.2）。

### 2.7 数据保留与归档（已实现）

- 180 天清理策略；细粒度删除与匿名化（FR-19）。
- `DataRetentionServiceImpl` 实现清理；保留索引覆盖 `wx_message` / `wx_session` / `log_tool_call` / `biz_pet_profile` 常用检索列。

### 2.8 在线配置热生效（已实现）

- `DynamicConfigService`（接口）+ `DynamicConfigServiceImpl`（三级缓存读取 + 类型解析 + 降级回退，永不抛异常）。
- `ConfigAdminService`：类型校验 → 落库 → 缓存失效 → 审计；非法值被拒（400）；密钥落审计时遮罩。
- 编排器、兜底文案、strict-mode、fail-closed 等改为运行时读取，免重启生效（FR-18）。

### 2.9 回放调试台（已实现）

- `ReplayService`：工具调用干跑重放 + 一致性复现（A-2）。
- 工具声明 `readOnly()`（默认 false）；非只读工具重放时被拦（`skipped=true, skipReason=NOT_READ_ONLY`）。
- 端点：`POST /api/tool-logs/{id}/replay` 与 `/replay`；前端 `views/tool-log/replay.vue`（权限码 `toolLog:replay`）。

### 2.10 多模型路由（已实现）

- `LlmClientRouter`（`@Primary`）：按运行时 `llm.provider` 路由；目标实现未装配则回退并 WARN。
- `provider()` 汇报真实生效者，便于排查"实际用了哪个模型"（B-2）。

### 2.11 管家设置后台（已实现，转型）

- 原"管理后台"轻量化为"管家设置"：用户档案维护、在线配置编辑、回放台。
- 权限码集中（`config:*` / `user:*` / `toolLog:replay`）；路由 meta 与守卫同名同源。
- 不作为"搭建控制台"——衔光预置人格、零配置，不提供人设 / 音色 / 知识库配置界面。

### 2.12 流式输出与实时观测（FR-08，已实现）

- `ConsoleController` 暴露 SSE 通道 `GET /api/sse/console`；`ConsoleEventBuffer` 维护**环形缓冲（上限 100）**，支持 `Last-Event-ID` 断线续传与心跳保活。
- 编排过程中的事件经 `ConsoleEventRelay`（`@EventListener`）投递；鉴权支持 `JwtAuthenticationFilter` 的 `?token=` 查询参数回落（`EventSource` 无法自定义 Header）。
- 前端 `utils/sse.ts` 封装自动重连；提供管理后台实时观测台。
- **局限（如实标注）**：本轮的 `message_delta` 为**终态一次性推送**（用于观测）；真 token 级流式需 `LlmClient.stream()` 重构，列入后续迭代。

### 2.13 会话与工具调用监控（FR-17，已实现）

- `MonitorService`：六类**只读聚合**（概览 / 趋势 / 成功率 / 意图分布 / 延迟 / 降级），全部走现有落表数据，不新增写路径。
- `MonitorController` 暴露 `/api/monitor/*`；前端监控页（概览 / 会话 / 工具日志）用 ECharts 渲染四图，独立分包。
- **局限（如实标注）**：意图分布以「工具调用归因」近似（系统未持久化 LLM 意图域），未新增 `wx_message.intent` 列。

### 2.14 降级与拦截看板（A-3，已实现）

- 呈现四项质量度量：**降级触发率**、**四层异常分布**、**执行性幻觉拦截计数**、**对外泄漏 KPI**（后者恒 0，因发送前即拦截）。
- 降级率 = `status ∈ {2 降级, 3 超时}` / 总量；幻觉拦截以编排器一致性拦截处补写 `log_audit`（`reg_type=SAFETY`）为计数源。
- **四层分布的数据来源（迭代 4 W1 起为两表合并）**：
  - **L3 / L4**：`log_tool_call.error_type` 归类（该表天然只承载工具层 + SAFETY 审计的 L4）；
  - **L1 / L2**：`log_anomaly_event`（V1.0.10）按**显式 `layer` 列**直接聚合——埋点覆盖 SRS 2.3.5 的
    接入层判据（`SIGNATURE_INVALID` / `TIMESTAMP_OUT_OF_WINDOW` / `MSG_DUPLICATED` / `UNKNOWN_MSG_TYPE`）
    与认知层判据（`LLM_TIMEOUT` / `LLM_UNAVAILABLE` / `LLM_INVALID_OUTPUT`，取 `LlmException#errorType()`）。
  - 埋点位置：`WechatCallbackController`（验签 + 幂等）、`MessageDispatcher`（未知类型回落）、
    `AgentOrchestratorImpl`（两处 `catch (LlmException)` 分支，经 `AnomalyNotice` 事件解耦，不新增构造器依赖）。
- **仍存局限（如实标注）**：① L2 的「意图置信度不足」判据走的是 `LlmIntentClassifier → IntentResult.unknown()`
  的**正常追问澄清路径**（BR-08），非异常分支，故未计入 L2 埋点，看板上 L2 仅覆盖 LLM 调用失败三类；
  ② 埋点为 best-effort（写库失败仅 WARN），极端故障下计数可能偏低而非虚高；③ `log_anomaly_event` 尚未纳入
  180 天留存清理（与 `log_audit` / `log_rate_limit` / `log_orchestration_trace` 同状态，见 §7.9）。

### 2.15 档案变更留痕（A-4，已实现）

- 档案写操作记录**字段级 before/after diff**，形成可查询的变更历史；复用 `log_audit`（`reg_type=PROFILE`），不新增表。
- `PetProfileServiceImpl.audit()` 以 `normalize` 白名单将 camelCase 入参映射为 snake_case 存量字段名，并剔除系统字段，避免 diff 噪声。
- `ProfileHistoryController` 暴露 `GET /api/profiles/history` 供后台查询。

### 2.16 超时预算时序瀑布（A-5，已实现）

- 编排器以 `System.nanoTime()` 记链路起点，为**每轮 LLM 调用**（`LLM_ROUND`）与**每次工具调用**（`TOOL`）记录 span（相对偏移 / 耗时 / 状态）。
- 链路结束组装 `OrchestrationTracedEvent`（含 `totalMs` / `totalBudgetMs` / `rounds` / `exceededBudget`）→ 落 `log_orchestration_trace`（V1.0.9）→ `GET /api/monitor/trace/{traceId}` → 前端甘特瀑布图（红色虚线标注 25s 预算线）。
- 使 SRS 4.4.2 的 SC-01~SC-05（5 轮 / 3 并行 / 25s 总预算）从文档条款变为**可核查事实**。

### 2.17 任务型多步会话（FR-24，已实现）

- `TaskSessionService`：追问时建任务 → 用户回复**优先槽位填充**（`SlotFiller`，确定性规则、不调 LLM）而非全量重识别 → 槽位齐备 `resume` 恢复原任务执行。
- **追问上限 3 次（BR-33）**：连续 3 次无法填充即放弃，并给出明确说明，不出现第 4 次追问；多任务并存**上限 2 个**（栈式）。
- **超时 10 分钟**无交互即结束并清理；话题明显切换则中断并提示"已暂停之前的操作"；Redis 故障视为任务取消。
- **存储分离（BR-34）**：任务上下文 `{taskType, requiredSlots, filledSlots, expireAt}` 落 `wx_session.task_context`（已存在列，无需迁移），活跃态存 Redis `task:{openid}`（TTL 10min），与 LLM 上下文键 `conv:{openid}` **完全分离**。
- 状态同步至 `Session.state=TASKING` 供后台观测；`TaskController` 暴露 `GET /api/tasks/{sessionId}` 与 `POST /api/tasks/{sessionId}/abandon`，**不暴露用户侧写接口**。

### 2.18 环境自检（Startup Doctor，A-1，已实现）

- `StartupDoctor`（`StartupDoctorImpl`）逐项校验 **DB / Redis / 微信 / LLM / TTS / 物流 / 地图** 的连通性、运行模式（Mock/Real）与配置校验结论，输出结构化体检报告 `DoctorReport`。
- 端点 `GET /api/doctor`（`DoctorController`，`@PreAuthorize("isAuthenticated()")`，任意已认证角色可用）；**体检过程不抛异常，故该端点永不为 5xx**。
- 与 `PlaceholderConfigValidator`（G3 占位符校验）配合，直接对抗前身"配置齐全但链路为空"的失败模式。
- 前端在仪表盘（`views/dashboard`）呈现体检结果。

### 2.19 个人状态库（W6，地基已落地）

- **定位**：跨会话持续生长的**个人知识**（人 / 地 / 物 / 偏好 / 惯例 / 事实），带溯源，是 [2.20 事件与触发引擎](#220-事件与触发引擎规划迭代-4) 与 [2.21 主动执行与承诺闭环](#221-主动执行与承诺闭环规划迭代-4) 两层的数据地基。
- **不是上传式 RAG**：条目由**每轮成功对话结束后自动抽取**产生（生长式），不依赖人工灌库；抽取失败或无产出时链路行为与改动前完全一致。
- **单表落点**：`biz_memory_item`（V1.0.11）。同一 `(openid, kind, name)` 为一条生效事实，冲突时**新值覆盖旧值**（旧行转 `SUPERSEDED` 并保留 `supersedes_id` 链），重复提及则 `hit_count + 1 / last_seen_at` 刷新——覆盖与强化皆可回溯。
  - `kind`：`PERSON / PLACE / THING / PREFERENCE / HABIT / FACT`；**承诺（COMMITMENT）不在本表**，与 `biz_commitment` 一并留待 W8（无触达通道的承诺是空头承诺）。
  - `origin`：`AUTO_EXTRACT`（已用）/ `TOOL`（**预留未启用**，工具主动写入待 W8 的 `remember`）。
  - **溯源**：`source_session_id` + `source_trace_id` + `extractor` + `confidence`。溯源指向会话与编排链路而非微信 MsgId——编排层看不到接入层 MsgId，且 `wx_message` 无 `trace_id` 列，故不设 `source_msg_id`（不留填不上值的列）。
- **生长管道**：编排器成功产出终态回复后发布 `MemoryGrowthNotice` → `MemoryGrowthListener`（自带**单线程 + 64 队列**的守护线程池）→ `LlmMemoryExtractor`（约束式 JSON 抽取，5s 超时，token 计入 `CostBudgetService`）→ `MemoryStore.upsert`。队列满即丢弃并计数（`droppedCount()` 可查），**不背压、不阻塞用户链路**。
- **召回注入**：`MemoryRecallService.buildRecallBlock(openid)` 以一条 `system` 消息注入本轮上下文（自带上限：条数 + 字符数，越界即截断），块内首行明示「不得据此编造已执行的动作」，与 BR-04 / 一致性校验语义保持一致；召回失败**放行不阻塞**（fail-open）。
- **热配置（`sys_config`，V1.0.12 播种）**：`memory.growth.enabled`（**默认 false**）、`memory.growth.max-items`（默认 5）、`memory.recall.enabled`（默认 true）、`memory.recall.max-items`（8）、`memory.recall.max-chars`（600）。生长默认关闭是因为它按消息计费地增加一次模型调用（G-32/G-33「预留未启用」口径）；召回只多一次索引读，故默认开启。**只开召回不等于状态库在用**——库空则召回为空。
- **PII 归属（FR-19）**：条目是对话的**派生 PII**。`scope=CHAT/ALL` 的用户数据删除会一并物理清空该 openid 的条目；留存任务只按 180 天清理 `SUPERSEDED` 历史，**生效事实不自动过期**（退出只有两条路径：被新事实覆盖、或用户删除数据）；合规报告的基数分母含 `biz_memory_item`。
- **隔离**：所有读写以 `openid` 为强制条件（BR-07）；日志中的 openid 经 `MaskUtils` 脱敏（BR-21）。
- **代码落点**：`domain/memory`（`MemoryWrite` / `MemoryFact` / `MemoryStore` 端口）、`application/memory`（抽取 / 监听 / 召回）、`application/admin/MemoryAdminService` + `interfaces/admin/MemoryController` + `interfaces/dto/memory/MemoryItemVO`（W6-b 后台）、`infrastructure/persistence/{entity,mapper,repository}`、`common/enums/Memory{Kind,Status,Origin}`。
- **后台界面（W6-b，已实现）**：`GET /api/memories` 分页只读列表（过滤 `openid`/`kind`/`status`，按 `last_seen_at` 倒序，出参 openid 经 `MaskUtils` 脱敏，BR-21），SUPER_ADMIN / OPERATOR / AUDITOR 可读（BR-23 口径同监控，AC-E9）；`DELETE /api/memories/{id}` 为**人工纠错**入口，**仅 SUPER_ADMIN**，逻辑删除（置 `deleted_at`，与 `live_marker` 生成列一致：删除后 `(openid, kind, name)` 槽位释放、生长可重新写入），并写 `log_audit`（`reg_type=MEMORY`，前值快照仅含 kind/name/content/origin）；**不提供编辑**——修正语义由生长管道的「覆盖」承担，避免人工值与自动值争抢同一事实。前端为 `views/memory` 只读页（菜单「个人状态库」，删除按钮经 `v-permission` 仅 SUPER_ADMIN 可见，后端独立鉴权兜底）。
- **剩余缺口（如实标注）**：条目纠错只有「删除」没有「改错后保留」路径——误抽取删除后依赖下一轮对话重新生长；审计快照不含完整行（如 `source_trace_id`），如需全链路取证仍需查库。

### 3.8 关键运行时机制

| 机制 | 说明 |
|---|---|
| Agent Loop | 多轮工具编排受轮次/并发/超时硬约束（SC-01~SC-05）；未注册工具判 NOT_EXECUTED |
| 先回执后推送 | 回调 ≤700ms 回执，终态异步推送（BR-06） |
| 执行一致性校验 | 声称成功但无执行记录 → CLAIM_UNSUPPORTED 拦截 |
| 内容安全 Fail-Closed | 词库不可用时按 Fail-Closed 处理 |
| 配置热生效 | 运行时读取，改后免重启 |
| 回放护栏 | 非只读工具干跑重放时跳过 |
| 多模型路由 | 运行时 `llm.provider` 路由，缺实现回退 + 告警 |
| SSE 观测通道 | 编排事件入环形缓冲（100），`Last-Event-ID` 续传 + 心跳；`?token=` 回落鉴权（FR-08） |
| 链路时序埋点 | `System.nanoTime()` 记起点，逐 span 记录并落表；超预算标 `exceededBudget`（A-5） |
| 任务会话续接 | 追问建任务 → 槽位填充优先于全量重识别；≤3 次放弃、10min 超时清理（FR-24） |
| 限流 Fail-Open | 限流组件异常时放行，避免误伤正常请求（FR-20） |
| 数据保留清理 | 180 天定时清理 + 细粒度删除 + 匿名化（FR-19）；状态库仅清理已覆盖历史，生效事实不自动过期（W6） |
| 状态库生长 / 召回 | 每轮成功对话后异步抽取（独立线程池，队列满即丢弃）；召回以一条 system 块注入本轮上下文，失败放行（W6，见 §2.19） |

## 第 6 章 维护指南

### 6.1 冷启动验证（结项必做）

- **教训**：单测全绿 ≠ 应用能启动。多构造器 Bean 未标 `@Autowired` 会在 `java -jar` 时失败。

### 6.2 已知启动级坑

| 现象 | 根因 | 处置 |
|---|---|---|
| 启动即 `NoSuchMethodException` | 多构造器 Bean 未标 `@Autowired` | 生产构造器加 `@Autowired` |

| Flyway 拒绝继续 | `flyway_schema_history` 残留 `success=0` | 删除该行后以修正脚本重试 |

### 6.3 日志与诊断

- 限流 / 审计 / 工具调用均有落表，可用 SQL 检索。

- 多模型路由 `provider()` 可查真实生效模型。

```powershell
powershell -File scripts/e2e-smoke.ps1 -AdminPassword Admin@123456
```

### 6.5 后端进程管理

- **Maven 启动器**：本机 `mvn` 脚本在 Git Bash 下因 `MAVEN_HOME` 解析为 unix 路径导致 `找不到 Launcher 类`。可用 Windows 风格路径直接调 java 引导：`java -Dfile.encoding=UTF-8 -cp "D:/apache-maven-3.9.15/lib/boot/plexus-classworlds-2.9.0.jar" -Dclassworlds.conf="D:/apache-maven-3.9.15/bin/m2.conf" -Dmaven.home="D:/apache-maven-3.9.15" -Dmaven.multiModuleProjectDirectory="<backend 绝对路径>" org.codehaus.plexus.classworlds.launcher.Launcher -B -o clean verify`。**离线 `-o` 现已可用**（本地仓库已含 `spring-boot-starter-parent:3.3.4`，实测全量 verify 通过）；`-Dfile.encoding=UTF-8` 必带，否则中文编译错误信息显示为乱码，掩盖真实报错。
- **D8 教训**：单测全绿 ≠ 能启动；多构造器 Bean 须显式 `@Autowired`；结项前必做 `java -jar` 冷启动（W4 为单构造器，已规避）。
- **Flyway**：`CREATE INDEX IF NOT EXISTS` 在 MySQL 报错，改普通 `CREATE INDEX`；改迁移文件名须 `clean package`。
- **`test-compile` 会骗人**：增量状态可能报 `Nothing to compile — all classes are up to date` 而漏掉构造器参数个数变更导致的测试编译失败；**结项信号只认 `clean verify`**。
- **curl 传中文 JSON 体**：Git Bash 下 `curl -d '{"reason":"中文…"}'` 会被后端判为 `10002 参数格式非法`（请求体编码问题，非产品缺陷）；验证时改 ASCII 文案，或改用 PowerShell 发体。
- **终端乱码 ≠ 库内乱码**：`mysql` 客户端在 Windows 控制台输出中文为乱码时，用 `SELECT CHAR_LENGTH(col), LENGTH(col)` 判定（UTF-8 汉字应为 1 字符 / 3 字节）再下结论。
- **管理员口令未知**：不要重置或猜测既有库口令；新建空库 + `ADMIN_INIT_PASSWORD` 播种全新 superadmin 是取得 AC-E1/E3/C1 证据的可复现做法（§7.10）。
- **日志/口令**：`tail` 含 token/口令的日志会触发审批拦截，用 `grep -c` 取计数。
- **前端**：勿走 npm shim（managed node 会拉 wsl 被拦），直接 `node.exe node_modules/<pkg>/bin` 调用；`vue-tsc`/`vite`/`eslint`/`vitest` 同理。
- **出网**：沙箱 `git push` 等可能 `errno=10061`，需项目外手动推送。
- **Vite 代理指向**：dev server 代理默认 `http://localhost:8080`（`vite.config.ts`），而本机 8080 常被占用、实证 jar 起在 8081——浏览器实证须用 `VITE_API_PROXY_TARGET=http://localhost:8081 npm run dev` 启动，否则 `/api/**` 全部落空。
- **前端 lint 基线**：`npm run lint`（`--max-warnings 0`）在既有 `views/monitor/console.vue` 上有历史格式告警，非门禁脚本的一部分；判断标准是**本次改动文件单独跑 eslint 干净**。
